# NewsDigestBot

Автоматически собирает новости из RSS и API, отбирает материалы, оформляет посты через ИИ и публикует их в Telegram по расписанию. Поддерживает OpenAI, Google Gemini, CLODEX и свой OpenAI-совместимый API; отдельные посты или дайджест, веб-панель и автообновление из GitHub.

## Быстрая установка

Поддерживаются **Ubuntu 22.04+ и Debian 12+**, архитектуры amd64 и arm64. Нужны права root (или sudo) и токен из [BotFather](https://t.me/BotFather).

**Чистый сервер: установка всех компонентов и запуск через systemd**

Выполни от root; если вошёл обычным пользователем, сначала `sudo -i`:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/romanich237/NewsDigestBot.git
cd NewsDigestBot
bash deploy/install.sh
```

Установщик автоматически ставит системные Node.js 22 LTS и npm, Git, curl, сертификаты, Python 3, компилятор и инструменты для SQLite. Подходящие системные Node.js 20.19+ и npm сохраняются. npm входит в пакет Node.js от NodeSource, отдельно выполнять `apt install npm` не нужно. Далее запускается мастер всех настроек, устанавливаются зависимости проекта и запускается systemd-сервис. Установщик отдельно спрашивает, нужна ли веб-панель. При отказе она отключается и Nginx/Certbot не устанавливаются для неё. При согласии можно включить автоматические Nginx и SSL: мастер запросит домен, порт, пароль и необязательный email; сертификат Let’s Encrypt выдаётся и продлевается автоматически. DNS домена должен указывать на сервер, порты 80 и 443 должны быть доступны.

Источники пакетов: репозитории ОС и [NodeSource](https://github.com/nodesource/distributions). Если Git уже установлен, команду `apt-get update && apt-get install -y git` можно пропустить.

**Вариант с PM2:**

Если проект уже скачан, системные зависимости можно установить отдельно: `sudo bash deploy/dependencies.sh`. На чистом сервере сначала установи Git командой выше.

```bash
git clone https://github.com/romanich237/NewsDigestBot.git
cd NewsDigestBot
sudo bash deploy/dependencies.sh
npm ci
npm run configure
npm run validate
npm install -g pm2
pm2 start ecosystem.config.js
pm2 save
```

Мастер запросит настройки Telegram, API, модели, источники и расписание. Для запуска после перезагрузки выполни `pm2 startup` и команду, которую он выведет.

**Если репозиторий уже скачан (Ubuntu или Debian):**

```bash
git clone https://github.com/romanich237/NewsDigestBot.git
cd NewsDigestBot
sudo bash deploy/install.sh
```

Выбери один способ запуска. Под PM2 и systemd проверка обновлений из `main` выполняется каждую минуту. Для канала боту нужны права публикации.

## Подробная настройка

Мастер предложит ввести все разделы конфигурации. Enter сохраняет значение, `-` очищает строку или список. Раздел можно пропустить, ответив «нет». API-ключи и пароли вводятся без отображения на экране. При повторном запуске текущие настройки сохраняются, перед записью создаётся резервная копия.

Основные поля `config.json`:

| Настройка | Что указать |
| --- | --- |
| `telegram.bot_token` | Токен бота |
| `telegram.allowed_user_ids` | Свои Telegram ID |
| `telegram.targets` | Получателей и каналы, включённых через `enabled: true` |
| `ai.provider` | `openai`, `google`, `clodex` или `custom` |
| `openai` / `google_ai` / `clodex` / `custom` | Ключ и модель выбранного провайдера |
| `news_sources` | RSS и дополнительные новостные API |
| `schedule.timezone` | По умолчанию `Europe/Moscow` |

Для канала добавь бота в администраторы с правом публикации. Для личных сообщений сначала открой бота и отправь `/start`. В `chat_id` укажи числовой ID или `@channelname`.

```bash
npm run validate
npm start
```

База `data.db` создаётся автоматически. Локальный `config.json` и база исключены из Git.

## Подключение ИИ

| `ai.provider` | Раздел настроек | Получение ключа |
| --- | --- | --- |
| `openai` | `openai` | [OpenAI Platform](https://platform.openai.com/api-keys) |
| `google` | `google_ai` | [Google AI Studio](https://aistudio.google.com/apikey) |
| `clodex` | `clodex` | [CLODEX](https://clodex.xyz/) |
| `custom` | `custom` | Ключ своего OpenAI-совместимого сервиса |

Также принимаются `chatgpt`, `gemini` и `google_ai`. Выбирается один провайдер. При отсутствии раздела `ai` сохраняется прежний порядок: настроенный Google, затем CLODEX. Автоматического перехода на другой платный API при ошибке нет.

### OpenAI

Добавь или обнови эти разделы в своём конфиге, сохранив остальные настройки:

```json
{
  "ai": {
    "provider": "openai",
    "format": "rich_html"
  },
  "openai": {
    "enabled": true,
    "api_key": "ВАШ_OPENAI_API_KEY",
    "model": "gpt-6-luna",
    "timeout_ms": 90000,
    "max_output_tokens": 8192
  }
}
```

### Google Gemini

Установи `ai.provider: "google"`, затем заполни:

```json
{
  "google_ai": {
    "enabled": true,
    "api_key": "ВАШ_GOOGLE_API_KEY",
    "model": "gemini-2.5-flash-lite",
    "timeout_ms": 90000,
    "max_output_tokens": 8192,
    "temperature": 0.2
  }
}
```

Google вызывается через нативный `generateContent`, OpenAI через `/v1/chat/completions`. Старое поле `google_ai.base_url` больше не используется. Для CLODEX сохранены `base_url`, `temperature` и совместимый endpoint.

После изменения провайдера, ключа или модели перезапусти процесс.

### Свой Base URL, API-ключ и модель

В мастере `npm run configure` выбери `ai.provider: custom`, затем заполни раздел «Свой OpenAI-совместимый API». Он также доступен при установке через `deploy/install.sh`. API-ключ вводится скрыто.

```json
{
  "ai": {
    "provider": "custom",
    "format": "rich_html"
  },
  "custom": {
    "enabled": true,
    "base_url": "https://api.example.com/v1",
    "api_key": "ВАШ_API_КЛЮЧ",
    "model": "идентификатор-модели",
    "timeout_ms": 90000,
    "max_output_tokens": 8192,
    "token_parameter": "max_tokens"
  }
}
```

Это фрагмент конфигурации: сохрани остальные разделы. URL указывается до `/chat/completions`, например `https://api.example.com/v1`; полный адрес этого endpoint тоже принимается, повторно он не добавляется. Поддерживаются HTTP и HTTPS, включая локальный сервер. Если сервис требует `/v1`, укажи его явно.

Запрос использует OpenAI Chat Completions: `messages`, `model`, заголовок `Authorization: Bearer <api_key>`. Сервис должен возвращать `choices[0].message.content` с JSON по промпту. Произвольные API с другим форматом запросов/ответов этот режим не поддерживает. Ключ не подставляется в URL.

Для моделей, которым нужен `max_completion_tokens`, поменяй `custom.token_parameter` с `max_tokens` на `max_completion_tokens`. Температура по умолчанию не отправляется; при необходимости добавь числовое `custom.temperature`.

Расходы записываются отдельно как `custom`. Тарифы OpenAI автоматически не применяются: укажи свои цены через `monitoring.custom.input_usd_per_million` и `monitoring.custom.output_usd_per_million`. Без них стоимость будет отображаться нулевой, даже если сервис платный. После настройки выполни `npm run validate` и перезапусти бота.

### Учёт расходов

Запросы записываются в `api_usage` отдельно для `openai`, `google_ai` и `clodex`. Для моделей из таблицы встроены отдельные цены входа и выхода. В Google выход включает thinking tokens. Оценка приблизительная: кэширование, дополнительные инструменты, специальные тарифы и налоги отдельно не рассчитываются.

Для другой модели задай собственные цены:

```json
{
  "monitoring": {
    "openai": {
      "input_usd_per_million": 0.10,
      "output_usd_per_million": 0.50
    },
    "currency": {
      "usd_rub": 90
    }
  }
}
```

Для Google используется раздел `monitoring.google_ai`. Заданные вручную цены имеют приоритет над встроенными, поэтому обновляй их при смене модели. У неизвестной модели без цен оценка равна нулю: это не означает бесплатный API. Для CLODEX по-прежнему доступна общая ставка `monitoring.clodex.usd_per_million_tokens`.

`/api` показывает последние 30 дней. Счётчик локальный, фактические списания проверяй у провайдера. Старые записи, сделанные до разделения провайдеров, автоматически не пересчитываются.

## Форматирование постов

ИИ возвращает обычные `title` и `summary` для совместимости и поле `body_html` с оформленным текстом. Исходная ссылка и название источника добавляются ботом отдельно.

| `ai.format` | Что доступно |
| --- | --- |
| `rich_html` | Ссылки, жирный, курсив, подчёркивание, зачёркивание, спойлеры, цитаты, код, заголовки, списки, таблицы, раскрываемые блоки, сноски и формулы |
| `html` | Обычный Telegram HTML; таблицы предлагаются текстом внутри `<pre>` |

Rich HTML отправляется через `sendRichMessage`. В старом конфиге без `ai.format` используется обычный HTML. Новый пример конфига включает Rich HTML.

```html
<h2>Обновление проекта</h2>
<p><b>Главное</b>, <i>уточнение</i> и <a href="https://example.com">ссылка</a>.</p>
<blockquote>Цитата</blockquote>
<table>
  <tr><th>Параметр</th><th>Значение</th></tr>
  <tr><td>Версия</td><td>1.2</td></tr>
</table>
<details><summary>Подробнее</summary><p>Дополнительный текст</p></details>
```

Текст ИИ ограничен 3500 символами вместе с разметкой; HTML не обрезается посередине. В обычном режиме целое сообщение должно укладываться в 4096 символов: для длинных выпусков выбирай `digest.mode: "single"`.

Telegram проверяет разметку при отправке. При ошибке отправки бот не помечает весь выпуск опубликованным. Отдельные посты, уже отправленные до ошибки, могут повториться при следующем запуске. Пользовательские эмодзи требуют действительных ID и соответствующих прав Telegram.

[Все форматы Telegram](https://core.telegram.org/bots/api#rich-message-formatting-options).

| `max_input_chars_per_item` | Длина входного описания |
| `max_llm_calls_per_run` | Ограничение вызовов при дополнительной обработке |

При ошибке ИИ сохраняется существующий запасной сценарий: повторная обработка отдельных новостей, затем обычные карточки из исходных материалов. Эти дополнительные запросы могут расходовать API-квоту. Текст не выдумывается при отсутствии источников.

## Расписание и получатели

По умолчанию пример задаёт случайный интервал 30–60 минут. Одинаковые `interval_min_minutes` и `interval_max_minutes` дают фиксированный интервал.

Для cron установи оба интервала в 0 и укажи, например:

```json
{
  "schedule": {
    "interval_min_minutes": 0,
    "interval_max_minutes": 0,
    "cron": "0 * * * *",
    "timezone": "Europe/Moscow"
  }
}
```

Включённые `telegram.targets` получают публикации автоматически. Для каждого получателя выпуск собирается отдельно. Бот должен работать в назначенное время.

Футер задаётся через `telegram.footer_text`. Упоминания `@username` превращаются в ссылки. Его также можно поменять в настройках Telegram, отправив `off` для удаления.

## Веб-панель и systemd

Веб-панель включается через `web.enabled`, порт задаётся в `web.port`, пароль в `web.password`. Мастер установки задаёт вопрос «Нужна веб-панель?». Для автоматической настройки HTTPS выбери «да» в следующем вопросе: `web.auto_ssl` включает установку Nginx и Certbot, `web.domain` задаёт домен, `web.ssl_email` позволяет указать email для сертификата. Эти действия выполняются через `deploy/install.sh`; отдельный `npm run configure` только сохраняет настройки. Она показывает статистику, позволяет запустить выпуск и поменять режим, интервал, ссылку и футер.

Для установки на Ubuntu 22.04+ или Debian 12+ с systemd:

```bash
sudo bash deploy/install.sh
```

Установщик автоматически устанавливает системные зависимости, копирует проект в `/opt/news-digest-bot`, создаёт пользователя `newsbot` и сервис `news-digest-bot`. Он также предлагает домен, Nginx и сертификат Let's Encrypt; домен должен указывать на сервер. Используй один менеджер процесса: PM2 или systemd.

```bash
sudo systemctl status news-digest-bot
sudo journalctl -u news-digest-bot -n 100 --no-pager
sudo systemctl restart news-digest-bot
```

## Автообновление из GitHub

При запуске под PM2 или systemd бот запускает отдельный процесс проверки GitHub. По умолчанию он проверяет ветку `main` каждую минуту и устанавливает новый коммит, даже если номер версии не изменился.

```json
{
  "updates": {
    "enabled": true,
    "autoInstall": true,
    "intervalSeconds": 60,
    "repository": "romanich237/NewsDigestBot",
    "branch": "main"
  }
}
```

| Поле | Действие |
| --- | --- |
| `enabled` | Включить проверку; при `false` обновлений нет |
| `autoInstall` | При `false` только проверять и записывать доступный коммит |
| `intervalSeconds` | Пауза между проверками, минимум 60 секунд |
| `repository` | Репозиторий в формате `owner/name` |
| `branch` | Ветка, по умолчанию `main` |

В старом конфиге без `updates` действуют указанные значения по умолчанию. При запуске через обычный `node` или `npm start` без менеджера процесса доступны только проверки: автоустановка не выполняется, чтобы бот не остановился без перезапуска.

### Как проходит обновление

1. Проверка нового коммита через Git. Токен для публичного репозитория не нужен.
2. Скачивание кода в `.updates/stage`, установка зависимостей и проверка синтаксиса JavaScript.
3. Приостановка новых генераций и ожидание завершения текущих, максимум 10 минут.
4. Замена файлов проекта и зависимостей. Настройки, SQLite, логи и резервные копии конфигурации сохраняются.
5. Завершение процесса бота. PM2 или systemd запускает новую версию.

При ошибке подготовки действующий бот продолжает работать. При ошибке замены восстанавливаются предыдущие файлы и зависимости. Журнал незавершённой установки проверяется при следующем запуске. Это не проверка работоспособности новой версии на реальных API: успешно установленная версия не откатывается автоматически из-за последующих ошибок Telegram или ИИ.

В Git-установке проверяются локальные изменения, выбранная ветка и возможность обновления без потери локальных коммитов. Рабочее дерево и Git-индекс приводятся к установленному коммиту. В установке без `.git` ведётся список управляемых файлов и их контрольных сумм; после первой автоустановки изменения этих файлов блокируют следующую. Локальные дополнительные файлы не удаляются. Конфигурация из нового `config.example.json` не перезаписывает твой `config.json`.

Работает и для `/opt/news-digest-bot` без `.git`: обновляющий процесс хранит отдельную копию Git в `.updates`. Нужны Git, npm, доступ к GitHub и npm registry, право записи в папку проекта и место для временной копии зависимостей. Установщик создаёт нужные права для `newsbot`.

### Проверка и логи

```bash
npm run update:check
cat .updates/status.json
```

Логи обновления помечаются `[UPDATE]` и попадают в обычные логи PM2/systemd. Состояние установленного коммита хранится в `.updates/installed.json`. Не удаляй `.updates` во время обновления.

### Первое подключение автообновления

Старая запущенная версия сама эту функцию не получит. Один раз обнови код вручную и перезапусти процесс.

Для Git + PM2, из папки проекта:

```bash
git pull --ff-only origin main
npm ci
npm run validate
pm2 restart news-digest-bot
pm2 save
```

Для старой установки без `.git` скачай свежий репозиторий в отдельную папку и запусти из неё `sudo bash deploy/install.sh`. Установщик сохранит существующие настройки в `/opt/news-digest-bot`, предложит их отредактировать и перезапустит systemd-сервис. Перед первым переходом сохрани резервную копию `config.json` и `data.db`.

## Повторная настройка

Для установки из Git:

```bash
npm run configure
npm run validate
pm2 restart news-digest-bot
```

Для systemd:

```bash
sudo -u newsbot node /opt/news-digest-bot/scripts/configure.js
sudo systemctl restart news-digest-bot
```

Мастер проходит Telegram и все типы получателей, OpenAI, Google, CLODEX, свой API, RSS и новостные API, состав выпуска, расписание, мониторинг, автообновление и веб-панель. Дополнительных получателей можно добавить по одному; списки вводятся через запятую. Для пользовательского JSON-источника сначала вводится его объект, затем можно изменить каждое поле.

Во время `deploy/install.sh` этот же мастер запускается автоматически. После успешной проверки конфигурации установщик запускает сервис. В разделе веб-панели отдельно задаются её включение и автоматическая настройка Nginx/SSL. При включённом `web.auto_ssl` установщик выпускает сертификат и активирует `certbot.timer` для продления; `web.host` устанавливается в `127.0.0.1`. Без автоматического SSL адрес прослушивания можно задать вручную. При ошибке выдачи сертификата установка останавливается с подсказкой проверить DNS и порты. При повторной настройке работающего бота новые значения применятся после перезапуска.

## Если возникла ошибка

| Проблема | Что проверить |
| --- | --- |
| Нет новостей | RSS, ключи источников, фильтры и историю опубликованных материалов |
| API 401/403 | Ключ, разрешения и доступность модели |
| API 429 | Баланс, квоту и частоту запросов |
| Незавершённый ответ | Увеличить `max_output_tokens` или уменьшить число кандидатов и новостей |
| Неверный HTML | Повторить генерацию; при необходимости выбрать `ai.format: "html"` |
| Слишком длинный пост | Режим `single` и более короткое резюме в промпте |
| Нет отправки в канал | `chat_id`, `enabled` и право публикации |
| Цена равна нулю | Наличие цены модели в `monitoring`; это может быть неизвестный тариф |

Проверка конфигурации и синтаксиса:

```bash
npm run validate
node --check src/main.js
node --check src/services/clodex_client.js
node --check src/bot/telegram_sender.js
```
